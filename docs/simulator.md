# GPS 格網遊戲介面

```sh
.venv/bin/python -m edge_rpg.simulator --port 8787 --gps-port 8765
```

開啟 http://127.0.0.1:8787 。目前預設每格 50 × 50 投影公尺（2,500 m²），每六個首次踏入的新格觸發一次 EVENT。起點先點亮一格；按五次「走進下一格」即可觸發示範旅人事件。按「走回上一格」再向前，計數不會增加。

三個頁面：探索世界、SQLite 資料、劇情生成。資料頁的 `exploration_totals` 顯示永久點亮總數、距下一事件的累積值及事件次數。生成頁顯示當次實際採用的環境、seed、權重及事件紀錄。

定位來源：

- **模擬試走**：按鈕移到相鄰方格，真實地圖上的位置和場景輸入都是測試資料。NPC 出現順序刻意安排，便於測試任務。
- **裝置 GPS**：需要瀏覽器定位權限，以及 HTTPS／localhost。電腦的定位未必有手機 GNSS 精度。
- **Android GPS Bridge**：手機 app 連到 `ws://電腦區網IP:8765/location`，瀏覽器選擇 Bridge 模式；手機和電腦須能經區網相連。

真實定位模式停用所有模擬移動按鈕。模擬用 `data/simulator/simulation-grid.db`；真實定位用 `gps-grid.db`，兩者獨立。重啟可恢復同一份資料庫；目前來源選擇預設回到模擬，可切回 GPS 查看實際探索。

地圖是 OpenStreetMap 線上圖磚，格網與存檔本機執行。無網路時底圖會顯示載入失敗，格網資料不會被清除。請勿把模擬路線或地圖點亮當成通行許可。

GPS 誤差超過 15 公尺、斷線、異常跳躍時不點亮新格。誤差範圍跨格線時等待更明確位置。相機關閉或沒有場景觀察不會阻擋 GPS 探索。

更改格子大小或事件門檻時，請使用 `--data 新目錄`，以免重新解讀舊存檔。詳細實作見 [劇情生成與物件機制說明](劇情生成與物件機制說明.md)。
