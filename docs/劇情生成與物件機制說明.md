# GPS 格網、劇情生成與物件機制

更新日期：2026-09-19。本文件描述目前預設 `square_visits` 模式，依照你的新玩法調整：**真實 GPS → 固定面積格子 → 首次進入永久點亮 → 累積新格觸發 EVENT**。原始 spec 的 H3、停留／觀察加權計分僅保留為 `legacy_h3` 相容路徑，不再是預設玩法。

## 1. 你實際會怎麼玩

預設每格 **2,500 平方公尺**（投影座標 50 × 50 公尺），每 **6 個新格**觸發一次事件。你說的「250～400／格子長」，目前解讀為以約 300 公尺的探索尺度設計，所以用 `300 / 50 = 6` 格。

這個 300 公尺是設計尺度，不是里程計：起點也算第一個新格，斜走、繞路、格線切入位置都會改變實際步行距離。真正門檻只有「首次點亮的格子數」。

```text
第一個有效新格 → 永久點亮，累積 1 / 6
第二至第五個新格 → 分別點亮，累積至 5 / 6
第六個新格 → 點亮＋建立 EVENT，累積回到 0 / 6
走回任一舊格 → 保留點亮，不增加計數、不重新生成事件
再走六個新格 → 下一次 EVENT
關閉後重開 → 已亮格、尚未達標的累積數、事件與任務都保留
```

相機不是點亮格子或觸發事件的必要條件。沒有相機時仍能完整探索，事件採用通用戶外情境。

## 2. 為什麼選 50 公尺格，以及怎麼處理 GPS 誤差

GPS.gov 說明，手機 GPS 在開闊天空下通常約有 4.9 公尺半徑的精度，建築物、橋樑、樹木附近會變差。[GPS 精度來源](https://www.gps.gov/gps-accuracy)

因此目前採 50 公尺而非 10 或 25 公尺格，給定位誤差更多空間。這是原型的工程取捨，仍須在你的手機與實際場域測試。

程式會檢查：

- 定位時間是否過期、逆序或在未來；斷線時不累積。
- 精度是否達到設定值：目前 `accuracy_m <= 15` 才能探索。
- 移動速度和位置跳躍；異常定位不計入。
- 新格邊界：距離四條投影格線的最短距離，需至少 `max(3, accuracy_m)` 公尺。誤差圈仍跨格線時顯示「等待更明確的位置」，不先寫入新格。
- 禁入 polygon 仍會阻止探索。`require_allowed_area: false` 讓新玩法不必先建立白名單；可改成 `true` 限制於指定場域。

格線判定採投影公尺，標準緯線設在臺灣附近的 25°；它是抑制漂移的保守規則，不是定位正確的保證。即使站著不動，有持續偏移的 GPS 仍可能誤判；需戶外實測後微調。

只計算 GPS 確實回報、且通過檢查的格子。兩筆位置之間不會自動補亮一整條直線。

## 3. 经纬度如何變成固定面積格子

實作：[grid.py](../src/edge_rpg/grid.py) 的 `SquareGrid`。

使用 pyproj／PROJ 的 WGS84 橢球等面積圓柱投影：

```text
+proj=cea +lat_ts=25 +lon_0=0 +datum=WGS84 +units=m

GPS (latitude, longitude) → 投影 (x, y)
column = floor(x / cell_size_m)
row    = floor(y / cell_size_m)
cell_id = sq1:50:column:row
```

同一位置、相同設定永遠得到同一格 ID；不會每次開遊戲以當下 GPS 重新產生網格原點。採用等面積投影是為了固定每格面積，不能直接拿等間距經緯度或 Web Mercator 像素當成等面積格子。[PROJ 投影說明](https://proj.org/en/stable/operations/projections/cea.html)

「50 × 50」是投影座標的邊長；真實地表邊長隨緯度略有差異，面積保持一致。在臺灣附近接近 50 公尺方格。瀏覽器的地圖顯示使用 Web Mercator，但**格子歸屬由後端等面積投影決定**。

格子大小、投影版本、事件門檻和 seed 記在 `world_meta`。既有存檔若設定不同會拒絕開啟，避免舊格被重新解讀；調整時請指定新資料目錄。

## 4. GPS 怎麼連到 UI

啟動：

```sh
.venv/bin/python -m edge_rpg.simulator --port 8787 --gps-port 8765
```

開啟 `http://127.0.0.1:8787`，定位來源有三種：

| 模式 | 位置來源 | 用途 |
|---|---|---|
| 模擬試走 | 下一格／上一格按鈕 | 檢查點亮、重走不計數、事件和任務 |
| 裝置 GPS | 瀏覽器 `navigator.geolocation.watchPosition` | 取得執行瀏覽器的裝置定位；桌機可能回報粗略定位 |
| Android GPS Bridge | 手機 app 經區網 WebSocket 傳 GNSS | 手機輸入 `ws://電腦或板子區網IP:8765/location` |

瀏覽器定位需 HTTPS 或本機 localhost，以及使用者的定位授權。直接用手機開普通區網 HTTP 網頁通常不能取得瀏覽器定位；目前 UI 伺服器只綁 localhost，Android Bridge 則可經區網連接 GPS 接收埠。[瀏覽器定位限制](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/watchPosition)

Android app 已有程式和建置好的 debug APK；本輪驗證的是受控定位與真實 WebSocket 協定，還沒完成手機戶外走動測試。板端與瀏覽器接收器不要同時佔用 8765；需要並行時設定不同埠。

GPS Bridge 執行緒只把資料放入佇列，主執行緒消費後呼叫 `World.gps()`。HTTP API、世界更新與 SQLite 都在同一主執行緒，避免跨執行緒寫資料庫。

## 5. SQLite 如何保存點亮與事件

| 表 | 功能 |
|---|---|
| `map_cells` | 每格永久 ID、`EXPLORED`、首次／最後到訪時間、事件 ID |
| `exploration_totals` | `visited` 總點亮數、`pending` 下次事件累積、`events_created` 次數 |
| `events` | 事件類型、發生格、狀態、生成時情境與實際使用的觀察 |
| `npcs`、`npc_memory` | NPC、關係與已完成任務等世界事實 |
| `quests` | 任務狀態、階段與獎勵 |
| `items`、`inventory` | 道具定義和玩家持有數量 |
| `event_log` | 到訪、事件、互動紀錄 |
| `scene_observations` | 經檢查、去重後的感知輸出，不是照片 |
| `world_meta` | 世界 seed 與不可混用的格網設定 |

`World._visit_square()` 在一筆交易中完成「新格點亮、累積＋1、若達標建立事件／NPC／任務、扣除六格累積」。如果事件建立失敗，整筆回滾，不會吞掉累積值。格 ID 是主鍵，事件的 `cell_id` 有 UNIQUE 限制。

現在檔案分開保存：

- 模擬：`data/simulator/simulation-grid.db`
- 瀏覽器／Android 真實定位：`data/simulator/gps-grid.db`
- 獨立板端程式：`data/world-grid.db`

舊 `simulation.db` 和 `world.db` 不刪除、不混入新格網；目前也沒有把舊 H3 探索轉成新方格的遷移工具。這些是單一玩家、本機存檔，沒有雲端帳號同步；「永久」指同一份 SQLite 持續保存。

資料頁可直接查看 `exploration_totals`，或執行：

```sql
SELECT visited, pending, events_created FROM exploration_totals;
SELECT cell_id, state, event_id FROM map_cells WHERE state = 'EXPLORED';
SELECT event_id, cell_id, type, payload_json FROM events;
```

## 6. EVENT 與劇情怎麼生成

實作：[world.py](../src/edge_rpg/world.py)、[events.py](../src/edge_rpg/events.py)、[simulator.py](../src/edge_rpg/simulator.py)。

```text
第六個新格
  → 取附近新鮮的相機觀察（可無）
  → map_context：環境轉成 RPG 情境
  → choose_event：seed ＋ 當前格 ID 決定抽選亂數
  → 依情境權重選事件
  → 寫入 SQLite，必要時建立 NPC 和任務
  → UI 依事件和任務階段顯示故事模板
```

格子一進入就觸發事件，當格的新相機結果通常尚未完成。因此可使用兩格邊長距離內、五秒內的最近一次有效觀察；沒有、過期或顯示室內時，就採 `generic_outdoor`。不會為了等待相機卡住事件。實際採用的觀察存入事件 `payload_json.source_observation`，劇情生成頁可查看；`null` 表示沒用相機。

環境映射按順序判斷，後面的命中可覆蓋前面：

| 輸入 | 情境 |
|---|---|
| 沒有觀察或場景信心不足 | 通用戶外 `generic_outdoor` |
| park／trail／forest_like 或 tree | 森林 `forest_path` |
| riverside／lake_side 或 pond／river／bridge | 水岸 `waterside` |
| campus／plaza／urban_outdoor | 聚落 `settlement` |
| statue | 古老地標 `ancient_landmark` |

預設信心門檻 0.65。事件權重如下，單位是相對權重：

| 情境 | 發現 | NPC | 資源 | 任務 | 戰鬥 | 地標 | 休息 | 稀有 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 通用戶外 | 30 | 20 | 15 | 10 | 10 | 5 | 8 | 2 |
| 森林 | 15 | 15 | 30 | 10 | 20 | 3 | 5 | 2 |
| 水岸 | 20 | 20 | 10 | 15 | 5 | 20 | 8 | 2 |
| 聚落 | 15 | 35 | 10 | 20 | 3 | 7 | 8 | 2 |
| 古老地標 | 10 | 15 | 5 | 20 | 10 | 30 | 5 | 5 |

亂數來源為 `SHA-256(world_seed + ':' + cell_id)`。同 seed、同格、同情境和權重才會得到相同抽選結果；生成後以資料庫結果為準，不因後來相機看見別的東西而重抽。

模擬器刻意選擇「第六個新格遇到旅人」的 seed，方便體驗任務。真實 GPS 使用設定檔的 seed `12345`，不保證第一個 EVENT 是 NPC。模擬步行每格推進約 36 秒虛擬時間，上一格相機觀察會過期，所以目前示範事件採通用戶外情境。

## 7. 物件辨識到底做了什麼

實作：[perception.py](../src/edge_rpg/perception.py)、[scene.py](../src/edge_rpg/scene.py)。

真機路徑是攝影機 → OpenCV 擷取 → RGB／縮放／量化 → TFLite 場景分類和 SSD 物件偵測 → `SceneObservation`。模型可經 Ethos-U delegate 推論，但目前工作區**沒有實際模型權重，也没有攝影機／NPU**。介面存在，不代表已完成硬體辨識驗證。

```json
{
  "timestamp": 1800000000,
  "scene": "park",
  "scene_confidence": 0.94,
  "objects": [{"class": "tree", "confidence": 0.91}],
  "indoor_probability": 0.02
}
```

目前保存的是物件類別與信心值，不包含每個物件的 GPS 座標、持續追蹤 ID 或畫面框。相似畫面以 16 × 8 灰階指紋去重，每格最多保存 16 筆；相機觀察不再為新格計數加分。

模擬器的 tree／bench／bridge／statue 是明確的測試輸入，不是讀取 OSM 地圖後辨識出來，也不是偷偷使用真實相機。

## 8. 真實物件、遊戲物件和圖示不同

| 類別 | 例子 | 實際作用 |
|---|---|---|
| 感知物件 | tree、bridge、statue | 影響事件情境和權重 |
| 遊戲角色 | Traveler NPC | 事件規則在 `npcs` 建立固定角色模板 |
| 道具定義 | herb、lost_charm | 啟動時建立在 `items`；不等於已持有 |
| 持有道具 | 背包的護符、藥草 | 接任務調查或資源事件後寫入 `inventory` |
| 顯示素材 | 人物 SVG、背包圖示、地圖 EVENT 記號 | 前端繪圖，沒有遊戲規則權限 |

相機看見樹不會把樹放進背包。取得護符來自任務階段與調查動作，現在不需要相機真的找到護符。

旅人任務：`AVAILABLE → 接受 → ACTIVE(stage 0) → 調查取得護符(stage 1) → 交談交付 → COMPLETED(stage 2)`。交付扣除護符、增加設定的 XP（預設 50）、提升關係並記錄 NPC 記憶；完成後重複交谈不再給獎勵。

資源／稀有事件調查給藥草；戰鬥使用固定規則扣血、給 XP；休息補血。這些結果都由 Python 規則決定，不讓語言模型修改。

## 9. 文字和地圖怎麼呈現

瀏覽器使用 OpenStreetMap 真實道路底圖，疊加後端方格邊界、未探索迷霧、已亮區域與事件點。底圖需要網路，載入失敗會明確顯示；SQLite 和 GPS 格網運算仍是本機執行。只請求目前視窗圖磚，保留來源標示，不批次下載整個地區。[圖磚使用規則](https://operations.osmfoundation.org/policies/tiles/)

板端 pygame 使用本地 MBTiles，可以離線顯示；未提供圖磚時顯示格網底色。人物插畫是固定 SVG，不代表真實地點存在一個人。

故事文字目前是事件類型＋任務階段的模板。可選的 [dialogue.py](../src/edge_rpg/dialogue.py) 使用 llama.cpp 改寫 NPC 台詞，但預設關閉、沒有 GGUF。它不能抽事件、改任務、發道具或寫 SQLite。
